## Issue exposed and corrected before the successful run

The first attempt reached job admission but the first browser submission timed out. Source inspection confirmed that a new guest's session cookie was issued only after job creation, making that first job difficult to recover if the response was lost. The candidate now establishes the session through `/api/fetch/clearance` before submitting a probe. That endpoint respects existing verified clearance and uses bounded JSON parsing. Timeout copy is now readable rather than exposing `signal timed out`.

The successful actual browser sequence recorded:

- Session setup: HTTP 200 in 4,046 ms, session cookie issued.
- Probe admission: HTTP 200 in 8,460 ms, no new session cookie required.
- Confirmation: HTTP 200 in 8,430 ms.
- Correct title, thumbnail, source and formats loaded; real upload, preview and download then completed.

The first attempt also stopped because the test helper's environment-key parser omitted digits and therefore missed the R2 variables. This was a test-runner error, corrected before any R2 upload. It was separate from the browser recovery fix. Its disposable database was removed, and its failure receipt was preserved.
